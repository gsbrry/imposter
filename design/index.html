Word of mouth

The game is played in a group, so every session is a chance to reach new people. Make sharing the natural end of every game.

Share card after each game

A bright result card ("Kabir fooled no one. The word was Mango.") sized for chat and stories, with the app link on it. One tap from Result.

Invite link with a reward

Each player has a personal link. Two installs unlock Bollywood. Message is prewritten and fun: "One of us is lying."

The phone is the ad

Pass and play means everyone in the room sees the app. Show the app name and link on the Pass the phone screen footer.

Share a custom pack

Pro users share their own word pack as a link. Friends need the app to play it.

Online rooms (Phase 2)

Joining a room from a link is the strongest install driver. Each new player arrives with a friend already waiting.

Ask for a rating at the high point

After a crew win with 5 or more players, ask once with the store's own review prompt. Never after a loss.

Rules that are easy to get wrong

Reveal parity

Crew and imposter use the same RevealCard with the same colours, size and timing. Only the strings change. Also match haptics and sound, or the imposter can be heard.

One primary action

Only one honey button per screen. Secondary actions are glass or text.

Plain text

Use straight apostrophes in all strings and save files as UTF-8, so broken characters never appear.

Category names

One word each. Change display names in the word data, not in screen code.

Clean-up found in the current code

  • utils has both .js and .ts copies of getWord and selectImposter. Keep the TypeScript version only.
  • package.json name is still bolt-expo-starter. Rename to impostr.
  • Player order is shuffled with sort(() => Math.random() - 0.5), which is not a fair shuffle. Use Fisher-Yates.
  • The colour keys in constants/theme.ts are called yellow but hold green. Rename them to match the new tokens.
  • No test setup and no test script yet. See the Testing tab.

Security guide

What protects revenue, user trust and store approval. Phase 1 is offline, so most risk is in purchases and builds. Phase 2 adds a server, which changes the picture.

Phase 1 findings in the current code

FindingRiskAction
Reviewer unlock: tapping the version label 7 times turns on Premium locallyHigh Anyone who learns the gesture gets every pack freeRemove it from release builds. Give Play reviewers access with license testers or a promo code instead.
Premium status is cached on the deviceMedium A rooted phone can edit the cacheCheck the RevenueCat entitlement on every launch; use the cache only when offline, with a short expiry.
RevenueCat keys in eas.jsonLow These are public SDK keys, designed to ship in the appFine to keep. Never add the secret API key anywhere in the app or repo.
Release signing keyMedium Losing it blocks updates; leaking it allows fake updatesKeep it in EAS credentials only. Confirm no .keystore other than the debug one is in git.
Suggest a category formLow Free text from usersLimit length, strip links, and say in the privacy policy where suggestions go.

Phase 1 additions

Word feed

HTTPS only. Validate the whole file (version, categories, plain short strings, under 1 MB) and reject it if anything fails. Treat words as text, never as code or HTML. Keep the bundled list as the fallback.

Crash reports

Turn off default PII in Sentry and strip player names. Keep the Sentry auth token in EAS secrets only.

Support reports

Send only what the user typed plus device model and versions. Limit length and rate. If a form endpoint is used, protect it from spam.

Rewards and invites (Phase 1.5)

  • Rewards counted on the device can be cheated on rooted phones. Keep rewards small (one pack), so cheating costs little.
  • Invite rewards need a trusted count of installs. Use the Play Install Referrer and a small server check, or reward the inviter only when the friend finishes one game.
  • Rate-limit invite rewards per device so one person cannot farm packs.

Online play (Phase 2)

Server decides roles

The server picks the imposter and sends each phone only its own word. Never send the word to the imposter's phone, even hidden. Otherwise anyone can read it from the network.

Room codes

Use 5 or more characters without look-alike letters. Rooms expire after 2 hours. Limit join attempts per device to stop guessing.

Names and clues

Filter abusive words in names and typed clues. Let the host remove a player.

Votes

Votes are counted on the server, one per player per round. Phones never see who voted for whom until the reveal.

Invite links

Validate the code on the server before opening a room. Links carry only the room code, never a name or ID.

No accounts needed

Use an anonymous device ID. Collect no phone numbers, emails or contacts.

Ads, privacy and store policy

  • Set the target age to 13 and over in Play Console. If children are in the audience, Families policy limits which ad networks you can use.
  • Show the consent form for ads where the law requires it (Google's consent SDK handles this).
  • Keep the Play Data safety form and public/privacy-policy.html in step with every new feature: analytics, ads, invites, online.
  • Keep blocking unneeded permissions in app.json, as today. Online play needs internet only.

Manual checklist

Game feel

  • In a dark room, crew and imposter screens look and sound the same
  • Pass the phone hides the word before handing over
  • Timer, tick and horn sounds respect the settings
  • Haptics respect the setting

Purchases

  • Buy each plan with a license tester
  • Restore on a second phone
  • Cancel and confirm packs lock again after expiry
  • No reviewer unlock in the release build

Edge cases

  • Airplane mode for a full game
  • Phone call during the clue round
  • Very long player names
  • Large system font size

Pause and exit

  • Pause stops the timer and sounds
  • Back button opens pause, not the previous screen
  • Exiting does not count in stats
  • Word never visible while paused

Word updates

  • Airplane mode uses bundled words
  • Broken or huge feed is ignored
  • Festival pack shows only on its dates
  • New words sheet shows once

Accessibility

  • TalkBack reads every button by name
  • Touch targets at least 44 x 44
  • Text contrast passes on cream and on glass
  • Reduced motion turns off pulses

Release gate

  • All automated tests pass
  • Manual checklist done on two Android phones
  • Internal testing track for 2 days with no crashes
  • Data safety form and privacy policy updated
  • Store screenshots updated to the new design
